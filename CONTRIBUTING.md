# Working on this

## Before writing anything

```bash
node tools/find.mjs <terms>
```

Searches names **and** doc comments across every module, including private
helpers. Five functions in this project were written twice because the second
version was named differently — `pma.js` reimplemented as `inspection.js`,
`buildRiserWebbing` as `buildRiserAssembly`, `ribOpenings` as
`reconcileRibOpenings`, plus `chunkInto` and `totalLineLength`. Grep did not
find them; this does.

## After writing anything

```bash
node tools/check.mjs
```

Six stages, one command. All six must pass.

## What the checks are for

| stage | catches |
| --- | --- |
| unit suite | the maths |
| Phase 1 audit | roadmap claims that have gone stale |
| full pipeline | modules that are right alone and wrong together |
| interface | features with no button, buttons with no effect |
| benchmark | performance regressions |
| self-audit | unused exports, stale numbers in prose, duplicate names |

The **full pipeline** stage carries a pinned baseline of 3 known problems.
Exceeding it fails; it is not a licence to add a fourth.

## House rules

**Measure, do not assume.** Several corrections in this project came from a
plausible-sounding number that was never checked. A 260 N anchor load turned
out to be ten times the real one. A "flat 6%" billow turned out to encode an
assumption nobody had stated. If a number can be taken from the model or from
the reference data, take it.

**Report the gap rather than closing it by tuning.** `docs/departures.md`
catalogues every place the implementation differs from the handbook, with the
measurement that justified it. "The handbook is wrong" is not a finding; "the
handbook gives X, the measurement gives Y, and here is the difference it
makes" is.

**A check that cannot fail is worse than no check.** It reports success. Two
in this project could not: a button test against a stub DOM whose
`querySelectorAll` returned `[]` unconditionally, and a convergence loop
watching a field that did not exist. Verify a new check fails when it should.

**Name what is missing.** Functions here return `missing: [...]` rather than
silently substituting zero. A bill of materials with no line data says so.

## Adding reference wings

`docs/collecting-reference-data.md` is a self-contained brief — no context
from the codebase needed. `data/reference/CATALOGUE.md` is the current
inventory, generated by `node tools/catalogue.mjs`.

The database is heavily Ozone-weighted. Wings from Advance, Nova, Gin, Niviuk,
Supair, Swing or Sol would be worth more than another Ozone.
